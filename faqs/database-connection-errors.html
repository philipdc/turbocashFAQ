How do I fix database connection errors in TurboCASH?

Last updated: November 17, 2025 | Category: Common Problems

Problem Description

Database connection errors are one of the most common issues users encounter when working with TurboCASH. These errors typically prevent the application from starting or accessing financial data.

Common Error Messages:
  • "Unable to connect to database"
  • "Connection timeout"
  • "Database server not found"
  • "Access denied for user"

Common Causes

  1. Incorrect connection settings - Wrong server address, port, or database name
  2. Database service not running - MySQL/PostgreSQL service stopped
  3. Firewall blocking connections - Port blocked by firewall or antivirus
  4. Invalid credentials - Wrong username or password
  5. Network issues - For remote databases, network connectivity problems

Solutions

1. Verify Database Service is Running

For Windows:

  1. Press Win + R and type services.msc
  2. Look for your database service (e.g., "MySQL" or "PostgreSQL")
  3. Ensure the service status is "Running"
  4. If not, right-click and select "Start"

For Linux:

sudo systemctl status mysql
# or
sudo systemctl status postgresql

# To start the service:
sudo systemctl start mysql

2. Check Connection Settings

Verify your connection configuration file:

  • Location: TurboCASH/config/database.ini
  • Check: Server address, port number, database name
  • Default MySQL port: 3306
  • Default PostgreSQL port: 5432

Example configuration:

[Database]
Server=localhost
Port=3306
Database=turbocash_db
Username=turbocash_user
Password=your_password

3. Test Database Connection

Use command-line tools to test connectivity:

MySQL:

mysql -h localhost -P 3306 -u turbocash_user -p
# Enter password when prompted

PostgreSQL:

psql -h localhost -p 5432 -U turbocash_user -d turbocash_db

4. Check Firewall Settings

Warning: Be cautious when modifying firewall rules. Only open necessary ports and restrict access appropriately.

Windows Firewall:

  1. Open Windows Defender Firewall
  2. Click "Advanced settings"
  3. Check "Inbound Rules" for MySQL/PostgreSQL
  4. Create a new rule if needed for port 3306 or 5432

Linux (UFW):

sudo ufw allow 3306/tcp  # MySQL
# or
sudo ufw allow 5432/tcp  # PostgreSQL

5. Verify User Permissions

Ensure the database user has proper permissions:

MySQL:

GRANT ALL PRIVILEGES ON turbocash_db.* TO 'turbocash_user'@'localhost';
FLUSH PRIVILEGES;

PostgreSQL:

GRANT ALL PRIVILEGES ON DATABASE turbocash_db TO turbocash_user;

Advanced Troubleshooting

Check Database Logs

MySQL logs: Usually in /var/log/mysql/error.log (Linux) or C:\ProgramData\MySQL\MySQL Server X.X\Data\ (Windows)

PostgreSQL logs: Check /var/log/postgresql/ (Linux) or C:\Program Files\PostgreSQL\X.X\data\log\ (Windows)

Prevention Tips

  • Set database service to start automatically on system boot
  • Keep regular backups of connection configuration files
  • Document any custom connection settings
  • Use strong passwords and change them regularly
  • Monitor database service health regularly
